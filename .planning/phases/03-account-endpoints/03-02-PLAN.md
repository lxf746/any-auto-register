   - Return StreamingResponse with media_type="application/json", Content-Disposition header

3. `POST /export/sub2api` — Sub2API format
   - Map body to AccountExportSelection
   - Call `_exports_service.export_chatgpt_sub2api(selection)`
   - Handle both single JSON and ZIP responses based on ExportArtifact.media_type
   - Return StreamingResponse with appropriate media_type and Content-Disposition

4. `POST /export/cpa` — CPA token format
   - Map body to AccountExportSelection
   - Call `_exports_service.export_chatgpt_cpa(selection)`
   - Return StreamingResponse

5. `POST /export/kiro-go` — Kiro-Go config
   - Map body to AccountExportSelection
   - Call `_exports_service.export_kiro_go(selection)`
   - Return StreamingResponse

6. `POST /export/any2api` — Any2API admin config
   - Map body to AccountExportSelection
   - Call `_exports_service.export_any2api(selection)`
   - Return StreamingResponse

For each export endpoint, create a helper function `_stream_artifact(artifact: ExportArtifact)` that:
  - If artifact.content is io.BytesIO, read and yield bytes
  - If artifact.content is str, encode to UTF-8 and yield
  - Set headers: Content-Disposition: attachment; filename="{artifact.filename}"
  - Return StreamingResponse(content_iterator, media_type=artifact.media_type, headers=headers)

Add two POST endpoints:

1. `POST /check-all` — trigger check for all accounts
   - Optional query param: platform (str = "")
   - Call `_checks_service.check_all_async(platform)`
   - Return ApiResponse(ok=True, data=result) — result is the task dict

   - Call `_checks_service.check_one_async(account_id)`
   - If result is None (account not found): raise HTTPException(404, "Account not found")

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client→API | Export requests may expose sensitive tokens (access_token, refresh_token) |
| API→Service | File generation happens in service layer — no additional trust boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-04 | Information Disclosure | Export endpoints return tokens/credentials | high | accept | Export is an explicit user action — tokens are needed for downstream tools (sub2api, CPA, etc.). Auth middleware protects endpoints. |
| T-03-05 | Denial of Service | Large account sets in export | low | accept | Export loads all matching accounts into memory. Current scale (hundreds to low thousands) is safe. StreamingResponse prevents response buffering. |
| T-03-06 | Tampering | Check-one with invalid account_id | low | mitigate | Service returns None for missing accounts → 404 raised. Path param validated by FastAPI int conversion. |
</threat_model>
