## Directory Purposes

**`api/`:**
- Purpose: HTTP request/response layer
- Contains: FastAPI routers with Pydantic request/response models
- Key files: `accounts.py` (CRUD), `task_commands.py` (task creation), `tasks.py` (task queries)

**`application/`:**
- Purpose: Business logic and orchestration
- Contains: Service classes that coordinate domain, infrastructure, and core
- Key files: `accounts.py` (AccountsService), `tasks.py` (task creation/execution/handlers, 959 lines)

**`core/`:**
- Purpose: Domain abstractions, base classes, registries, DB schema, utilities
- Contains: ABCs for platforms/executors/captcha/mailbox/identity, registration flow orchestration, DB models, registries
- Key files: `base_platform.py` (504 lines), `db.py` (641 lines), `registry.py`, `lifecycle.py`

**`domain/`:**
- Purpose: Pure data structures with no business logic
- Contains: `@dataclass` definitions for commands, queries, records, summaries
- Key files: `accounts.py` (AccountRecord, AccountQuery, AccountCreateCommand, etc.)

**`infrastructure/`:**
- Purpose: Database access layer using repository pattern
- Contains: Repository classes wrapping SQLModel sessions
- Key files: `accounts_repository.py` (391 lines), `provider_settings_repository.py`

**`platforms/`:**
- Purpose: Concrete platform plugin implementations
- Contains: One subdirectory per platform, each with `plugin.py`
- Key files: `chatgpt/plugin.py` (422 lines, most complex), `windsurf/plugin.py`

**`providers/`:**
- Purpose: Concrete provider implementations (captcha, sms, mailbox, proxy)
- Contains: One subdirectory per provider type, multiple modules per type
- Key files: `registry.py` (auto-discovery + factory)

**`services/`:**
- Purpose: Background runtime processes
- Contains: Task dispatcher, solver manager
- Key files: `task_runtime.py` (TaskRuntime class)

**`frontend/`:**
- Purpose: Web UI (Vite + TypeScript SPA)
- Contains: React/Vue frontend source, served as static files by FastAPI
- Key files: `src/`, `vite.config.ts`

**`tests/`:**
- Purpose: Test suite
- Contains: pytest test files and conftest
- Key files: `conftest.py`, `test_api_*.py`, `test_tasks_*.py`

## Naming Conventions

**Files:**
- snake_case for all Python files: `base_platform.py`, `task_runtime.py`
- One class per file preferred (except `core/db.py` which has all models)
- Platform plugins: `platforms/{name}/plugin.py`
- Provider plugins: `providers/{type}/{name}.py`

**Directories:**
- snake_case: `turnstile_solver/`, `customer_portal_api/`
- Lowercase: `api/`, `core/`, `domain/`, `platforms/`, `providers/`

**Classes:**
- PascalCase: `BasePlatform`, `AccountsService`, `TaskRuntime`
- ABCs prefixed with `Base`: `BasePlatform`, `BaseExecutor`, `BaseCaptcha`, `BaseMailbox`
- Models suffixed with `Model`: `AccountModel`, `TaskModel`, `ProviderSettingModel`

**Functions:**
- snake_case: `create_register_task()`, `load_all()`, `save_account()`
- Private functions prefixed with `_`: `_execute_register_task()`, `_build_platform_instance()`

**Constants:**
- UPPER_SNAKE_CASE: `TASK_TYPE_REGISTER`, `SOLVER_PORT`, `DATABASE_URL`
- Task status/type constants in `application/tasks.py`

## Where to Add New Code

**New Platform Plugin:**
- Create `platforms/{platform_name}/plugin.py`
- Decorate class with `@register` from `core/registry.py`
- Extend `BasePlatform` from `core/base_platform.py`
- Implement `check_valid()`, and registration adapters (browser/protocol/OAuth)
- Auto-discovered at startup — no registration code needed elsewhere

**New Captcha Provider:**
- Create `providers/captcha/{name}.py`
- Decorate class with `@register_provider("captcha", "{driver_type}")`
- Implement `solve_turnstile()` and `solve_image()` from `BaseCaptcha`
- Auto-discovered at startup

**New SMS Provider:**
- Create `providers/sms/{name}.py`
- Decorate class with `@register_provider("sms", "{driver_type}")`
- Implement `get_phone()` and `wait_for_code()` from `BaseSMS`

**New Mailbox Provider:**
- Create `providers/mailbox/{name}.py`
- Decorate class with `@register_provider("mailbox", "{driver_type}")`
- Implement `get_email()` and `wait_for_code()` from `BaseMailbox`

**New API Endpoint:**
- Add router in `api/{domain}.py` (or create new file)
- Create corresponding service in `application/{domain}.py`
- Register router in `main.py`: `app.include_router(new_router, prefix="/api")`

**New DB Table:**
- Add SQLModel class in `core/db.py`
- Add repository in `infrastructure/{name}_repository.py`
- Call `SQLModel.metadata.create_all(engine)` in `init_db()` (automatic)

**New Task Type:**
- Add constant in `application/tasks.py`: `TASK_TYPE_{NAME} = "{name}"`
- Add handler function `_execute_{name}_task(payload, logger)`
- Register in `execute_task()` handlers dict
- Create API endpoint in `api/task_commands.py`
