<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Platform registration → rate limit check | Rate limit check must not block legitimate requests; false positives degrade UX |
| SMS provider → rate limit check | Provider rate limit must not prevent account creation when provider allows |
| HTTP request → metrics recording | Metrics recording must not fail the request on error |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-05-01 | Denial of Service | rate_limit_metrics.record_usage | low | accept | Metrics recording is fire-and-forget; errors suppressed |
| T-05-02 | Tampering | check_platform_limit bypass | medium | mitigate | Rate limit check is in the flow layer, cannot be bypassed by platform plugins |
| T-05-SC | Tampering | npm/pip/cargo installs | high | mitigate | No new packages installed in this phase |
