  <action>
    Integrate `retry_with_backoff` from `core/utils/retry.py` into `core/http_client.py` `HTTPClient.request()` method (per D-04: "Integrate retry_with_backoff into HTTPClient request method").

    1. Add import at top of `core/http_client.py`: `from core.utils.retry import retry_with_backoff`.

    2. Replace the manual retry loop in `HTTPClient.request()` (lines 119-151) with a call to `retry_with_backoff`. The current loop does:
       - Try request
       - On 500+ status: sleep(retry_delay * (attempt+1)) and continue
       - On exception: sleep(retry_delay * (attempt+1)) and continue
       - After max_retries: raise HTTPClientError

    3. The new implementation should:
       - Define an inner function `_do_request()` that makes the single request attempt
       - Call `retry_with_backoff(_do_request, max_retries=self.config.max_retries, backoff_factor=self.config.retry_delay, exceptions=(cffi_requests.RequestsError, ConnectionError, TimeoutError), backoff_strategy="exponential", jitter=True)`
       - After the retry wrapper, check response status: if >= 500, raise an exception to trigger retry; if >= 400, return the response (client errors are not retried)
       - If retry_with_backoff exhausts retries, wrap the final exception in HTTPClientError

    4. The `backoff_strategy="exponential"` with `jitter=True` gives exponential backoff with random 0-1s offset, which is better than the current linear `retry_delay * (attempt+1)`.

    5. Add tests to `tests/test_gap_closure_integrations.py` covering the retry behavior with mocked HTTP responses.
  </action>
